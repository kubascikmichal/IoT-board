\section{Príklady podľa zadania}

V tejto kapitole sú príklady popísané sekvenčne po logických blokoch. Pri každej ukážke najprv stručne popíšem cieľ a motív riešenia, potom rozoberiem jednotlivé kroky, na ktoré treba pri implementácii dbať, a nakoniec uvádzam skrátený kódový výrez v poradí, v akom sa program číta. Texty obsahujú poznámky o možných chybách, predpokladoch o zapojení a návrhoch, ako daný blok rozšíriť.

\section{Servisný test dosky}
Tento príklad slúži ako rýchly self-test po flashnutí zariadenia. Cieľom je overiť základné periférie (displej, LED, senzory, tlačidlá, bzučiak) a získať rýchlu spätnú väzbu o tom, či sú piny a moduly správne zapojené. V texte uvádzam, ktoré merania sú deterministické (napr. ADC čítanie) a ktoré závisia na externých podmienkach (napr. svetelnosť), ako aj tipy na ladenie (kontrola napájania, sériový výstup, jednoduché multimeter kontroly).

\subsection*{Mapovanie pinov a zber výsledkov}
Najprv si nadefinujem piny, ktoré program používa, aby bolo jednoduché upraviť zapojenie podľa konkrétnej dosky. Zoznam \lstinline|results| slúži ako jednotný formát pre neskoršie zobrazenie výsledkov a uľahčuje rozšírenie testov alebo odoslanie reportu cez sériový port.
\begin{lstlisting}[language=Python]
from machine import Pin, PWM, I2C, ADC
import time

PIN_I2C_SDA = 1
PIN_I2C_SCL = 2
PIN_RGB_R = 7
PIN_RGB_G = 5
PIN_RGB_B = 3
results = []
\end{lstlisting}

\subsection*{Pomocné funkcie pre výsledky}
Pomocné funkcie izolujú opakujúcu sa logiku: \texttt{add\_result()} formátuje a ukladá výsledok testu (názov, stav, poznámka), čo zjednoduší tlač správy alebo export. \texttt{ask\_yes\_no()} sa používa na manuálne overenie vizuálnych komponentov (napr. či OLED skutočne zobrazuje text) a ukážem, prečo je vhodné mať takýto blok oddelene pre jednoduché testovanie.
\begin{lstlisting}[language=Python]
def add_result(name, ok, note=""):
	state = "PASS" if ok else "FAIL"
	results.append((name, state, note))

def ask_yes_no(question):
	while True:
		ans = input(question + " [y/n]: ").strip().lower()
		if ans in ("y", "yes", "a", "ano"):
			return True
		if ans in ("n", "no", "nie"):
			return False
\end{lstlisting}

\subsection*{Test OLED, RGB LED a WS2812}
V tejto časti sa zameriame na vizuálnu spätnú väzbu: krátky text na OLED potvrdí komunikáciu po I2C, diskrétna RGB LED overí základnú logiku výstupov a WS2812 reťazec demonštruje adresovateľné LED a správne časovanie dátového signálu. Poznámka: pri WS2812 je kritické správne napájanie a dostatočné časovanie; v texte spomínam ako testovať po jednom pixeli a na čo si dávať pozor pri viacnásobnom píne.
\begin{lstlisting}[language=Python]
def test_oled():
	i2c = I2C(0, sda=Pin(PIN_I2C_SDA), scl=Pin(PIN_I2C_SCL), freq=400000)
	oled = ssd1306.SSD1306_I2C(128, 64, i2c)
	oled.text("SELF TEST", 0, 12)
	oled.show()

def test_rgb_discrete():
	r = Pin(PIN_RGB_R, Pin.OUT)
	g = Pin(PIN_RGB_G, Pin.OUT)
	b = Pin(PIN_RGB_B, Pin.OUT)

def test_ws2812():
	np = neopixel.NeoPixel(Pin(PIN_LED_DATA), WS2812_COUNT)
	np[0] = (255, 0, 0)
	np.write()
\end{lstlisting}

\subsection*{Test bzučiaka, tlačidiel, fotorezistora a DHT}
Tu prichádzajú testy, ktoré zahŕňajú časovanie (bzučiak), čítanie digitálnych vstupov (tlačidlá), analógové meranie (fotorezistor cez ADC) a sekvenčné meranie (DHT senzor). V texte popisujem očakávané rozsahy hodnôt, ako si nastaviť debounce pre tlačidlá a prečo pri DHT senzore potrebujeme čakať medzi meraniami.
\begin{lstlisting}[language=Python]
def test_buzzer():
	bz = PWM(Pin(PIN_BUZZER), freq=1000, duty=0)
	for f in (523, 659, 784):
		bz.freq(f)
		bz.duty(512)

def test_buttons():
	buttons = [("USR1", Pin(PIN_BTN_1, Pin.IN)), ...]

def test_photo():
	adc = ADC(Pin(PIN_PHOTO))
	v = adc.read()

def test_dht():
	sensor = dht.DHT22(Pin(PIN_DHT))
	sensor.measure()
\end{lstlisting}

\subsection*{Spustenie testov a súhrn}
V hlavnej časti je cyklus, ktorý postupne vykoná jednotlivé testy a zapíše výsledky do `results`. Toto miesto je ideálne na doplnenie logovania do súboru alebo na odosielanie výsledkov cez sériový port/HTTP. V texte tiež navrhujem, ako pridať timeouty a opätovné pokusy pre nestabilné periférie.
\begin{lstlisting}[language=Python]
for fn in (test_oled, test_rgb_discrete, test_ws2812,
		   test_buzzer, test_buttons, test_photo, test_dht):
	fn()

print("=== SUMAR ===")
for name, state, note in results:
	print(name, state, note)
\end{lstlisting}

\section{Prerušenia a meranie dĺžky stlačenia}
Ukážka ilustruje použitie prerušení (IRQ) na efektívnu detekciu stlačenia bez náročného polling-u v hlavnej slučke. V texte rozoberiem debounce stratégie, bezpečnosť pri práci s globálnymi premennými v IRQ kontexte a prečo by sa v obsluhe prerušení nemali volať pomalé funkcie.

\subsection*{Stav a časovanie pre IRQ}
\begin{lstlisting}[language=Python]
from machine import Pin, I2C
import time

press_started = None
last_duration = 0
\end{lstlisting}

\subsection*{IRQ obsluha s debounce}
IRQ handler by mal byť krátky: iba zaznamenať čas začiatku alebo konca stlačenia a nastaviť príznak. Vysvetlím, ako merať čas pomocou \texttt{time.ticks\_ms()} a prečo je bezpečnejšie spracovať dĺžku tlačenia v hlavnej slučke, nie priamo v handleri.
\begin{lstlisting}[language=Python]
def make_irq_handler(name):
	def handler(pin):
		global press_started, last_duration
		if pin.value() == 0:
			press_started = time.ticks_ms()
		else:
			last_duration = time.ticks_diff(time.ticks_ms(), press_started)
	return handler
\end{lstlisting}

\subsection*{Pripojenie handlerov na tlačidlá}
\begin{lstlisting}[language=Python]
btn1 = Pin(39, Pin.IN)
btn1.irq(trigger=Pin.IRQ_FALLING | Pin.IRQ_RISING,
		 handler=make_irq_handler("USR1"))
\end{lstlisting}

\subsection*{Zobrazenie posledného stlačenia}
Program priebežne ukazuje poslednú nameranú dĺžku stlačenia.
\begin{lstlisting}[language=Python]
while True:
	print("Posledne stlacenie:", last_duration, "ms")
	time.sleep(0.2)
\end{lstlisting}

\section{Analógové meranie svetla}
V tejto kapitole popisujem meranie odporu fotorezistoru cez ADC a postup kalibrácie, ktorý zabezpečí zmysluplné percentuálne hodnoty v rôznych svetelných podmienkach. Upozorním na offsety ADC, potrebu filtrovania a ako zmerať minimálne a maximálne hodnoty prakticky.

\subsection*{Inicializácia ADC}
\begin{lstlisting}[language=Python]
from machine import Pin, ADC


adc.atten(ADC.ATTN_11DB)
\end{lstlisting}

\subsection*{Kalibrácia minima a maxima}
Kalibrácia spočíva v pokrývaní extrémov (tma vs. silné svetlo) a zapísaní týchto hodnôt, ktoré sa potom použijú na normalizáciu vstupu. V texte dávam tipy, ako vykonať viacnásobné merania a použiť klzavý priemer pre stabilnejší výsledok.
\begin{lstlisting}[language=Python]
min_v = 65535
max_v = 0
v = adc.read()
\end{lstlisting}

\subsection*{Prepočet na percentá}
Normalizácia spraví z ADC čísla ľahšie čitateľný výstup.
\begin{lstlisting}[language=Python]
def normalize(value, min_v, max_v):
	span = max_v - min_v
	return int((value - min_v) * 100 / span)
\end{lstlisting}

\subsection*{2. Vytvorím pomocné funkcie pre výstupy}
	Oddelené funkcie pre ovládanie výstupov zlepšujú čitateľnosť a uľahčujú viazanie rozhrania (mapovanie tlačidiel na akcie). Vysvetlím, ako mať čisté API pre zmenu stavu (napr. \lstinline|set_rgb(name)|) a prečo je dobré mať centrálny stav zariadenia, ktorý HTML stránka vie prečítať.

def set_rgb(name):

Spustenie AP modeluje režim, keď zariadenie poskytuje vlastnú sieť bez potreby existujúcej infraštruktúry. Popisujem, kedy je vhodné AP vs. STA režim, ako nastaviť jednoduché heslo a čo očakávať pri obmedzenom dosahu/kanálových konfliktoch.
